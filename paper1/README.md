# paper1: P1.1 rain-only reference population and P1.2 rain-only expectation model

Code for steps P1.1 and P1.2 of `Groundwater_Buffering_Research_Plan_v2_Ogallala.pdf` (section 5.3), plus the
parts of Step 0 they need: S0.1 blocks, S0.3 drivers, S0.5 water-table depth and S0.6 HAND. Updated on 2026-11-11
to cards P1.0-P1.2 of `Groundwater_Buffering_Papers_1_2_Detailed_Plan_v3_Ogallala.pdf` (see "Plan v3" below and
`docs/superpowers/specs/2026-11-11-paper1-v3-changes-design.md` in the repository).

## Where to change things
- `config.py` is the only settings file. It sets `RUN_ENV` (`"colab"` or `"local"`), `RUN_MODE` (`"test"`, `"focus"`
  or `"full"`), every rule threshold and every model setting. You can also set `P1_RUN_ENV` and `P1_RUN_MODE` as
  environment variables instead of editing the file.
- `docs/CONFIG.md` describes every setting and which stages it affects. It is generated by `python -m paper1 docs`.

## Run

- **Local:** run these from `G:\MSU_GWB\datasets`:

  python -m paper1 run p12        # P1.2            (needs torch: use the conda env SSM)

## Stages
Each stage writes to `<data root>/P1_rain_only[/_test|/_focus]/<stage>/<signature>/`. The signature changes
whenever the stage's code, the settings it uses, or its input stages change. A changed setting therefore writes
to a new folder, and older results stay where they are.

    tiles -> blocks, drivers, hand -> static (+counties) -> classes -> dryland -> reference -> verify_p11
    samples, folds -> train -> predict -> verify_p12

## Tests
`python -m paper1 test [unit|e2e|provenance|torch]`
- `unit` and `e2e` use synthetic data written in the exact file formats; `e2e` runs every stage up to `folds`.
- `provenance` recomputes sampled values from the source files in the local folder, using `tests/oracle.py`,
  which imports nothing from `paper1`.
- `torch` covers M1 and runs train, predict and verify on the synthetic data.

## Plan v3 (2026-11-11)
- **P1.0 block aggregates** (`step0/blocks.py`): 16-bin histograms of ET, NIRv and NDMI per block-month, and the
  observation support (Landsat 8/9 share, mean observation day, OpenET models kept, smallest / largest model value,
  clear-scene count). Change these before the aquifer-wide run: any edit to `blocks.py` means reading the tiles again.
- **Drought class**: monthly SPI-90 per gridMET cell from the lab drought file (`spi90d`), used only as a stratum.
- **Depth ladder** (`p1_1/rules.py`): rungs 60/30/15/10 m are stored as bits; the class rung is 15 m for herbaceous
  groups and 30 m for shrub, hay and woody blocks. The reference uses 30 m until a functional group x decile is
  listed in `config.DEPTH_ACCEPTED`. Workflow: run through `verify_p12`, read the ring test in its report, copy the
  entries you accept from `reports/depth_accepted_proposal.json` into `DEPTH_ACCEPTED`, rerun `reference` and `train`.
- **New rules / sets**: canal buffer (NHD type 336, 800 m), fire slot (MTBS, not loaded yet), `reference_irr3`
  (LANID pixels labelled in >= 3 years only), `reference_ring`; the HAND-only crop set is now the run-on diagnostic set.
- **P1.2 inputs**: measurement inputs per month, functional group (primary) with the CDL group as a secondary input,
  the previous year's functional group. Calibration strata: target x functional x tercile x season x drought x regime,
  merged upward (regime first, then tercile) below `CAL_MIN_N` calibration block-months.
- **Gates**: `verify_p11` decides G1a (it gates `samples`), `verify_p12` decides G1b. In `focus` / `full` mode a failed
  gate halts the stages it gates unless its name is in `GATE_OVERRIDE` (recorded in provenance); `test` mode only warns.
- **Python**: unit, e2e and provenance tests need scipy, geopandas and rasterio (the system Python here); torch tests
  need the SSM env. Run e2e before torch: torch reuses the upstream stages e2e writes.

## Known deviations from the plan (all recorded in the code)
- LANID stands in for the well and point-of-diversion registries. LANID is derived from greenness and ends in 2017.
  Kansas WIMAS (registry comparison and a known-zero set), MTBS fire perimeters and the USGS irrigation maps of
  2018-2020 are not on disk: their checks are reported as not assessed.
- GDE is a sensitivity check, not a rule. 97 % of natural cells have a GDE fraction above 0.
- SPEI, EDDI and the S0.4 events are not built (SPI-90 is read from the lab product for the drought strata).
- G1a does not fail on out-of-domain strata (fewer than 500 reference blocks): those go to P1.3 by design.
  It fails on V2, on an empty domain, or on a malformed `DEPTH_ACCEPTED`.
- Flow accumulation counts only drainage inside each HU8 window (local convergence, not total drainage area).
- The ring test's standard error counts block-years (block-months / 12); the coupling-slope criterion waits for P1.4.
- Only the 480 m scale is built so far; the 1/24° scale comes after 480 m passes verification.
